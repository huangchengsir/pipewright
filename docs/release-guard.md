# 发布护航与变更关联调查

发布护航在 Docker 镜像部署之外保存一份有期限的只读观察报告。流水线结果、观察任务状态、验证结果和原因调查分别展示；部署成功后容器退出，不会修改原流水线结果，但会在护航中记录失败。

## 发起观察

- **随本次发布观察**：在运行详情的镜像发布表单启用护航，选择目标和 5、10 或 15 分钟窗口，审阅计划，再执行原有发布。重新审阅计划会更新绑定；修改产物、目标、策略或健康门控后需重新确认。预采基线失败不会阻止发布。
- **从现在开始观察**：在运行详情或环境发布历史中，选择一次具有完整容器回执的部署尝试，再审阅并启动计划。此前的运行时间不计入覆盖，也不会补造发布前基线。

每次真实部署、重试或继续发布都有独立尝试。同一次运行的多次发布分别保留。升级前的历史可能没有容器回执或完整实际检出 SHA，因此无法追溯验证；需在后续真实部署后使用这些能力。

一个计划只能包含同一项目、明确环境的 1–5 个目标。默认观察 10 分钟，不采日志、不调用模型。状态每 30 秒采样；必选项为实际镜像版本与容器存活、重启和 OOM 状态，Docker 已配置健康检查时同时检查其状态。护航不会执行健康脚本、HTTP 探测或容器内命令。

## 阅读报告

报告展示计划、逐目标条件、采样覆盖、证据、时间线和调查：

| 验证结果 | 含义 |
| --- | --- |
| 通过 | 窗口内基础运行条件及采样覆盖达标；不代表业务可用性或采样间隔内绝无故障 |
| 失败 | 有绑定对象的明确违例，例如退出、OOM、重启或 Docker 健康失败 |
| 证据不足 | 身份、采样、连接或版本映射不能支持结论；不等同服务故障 |
| 不确定 | 同一条件存在尚未解决的可信冲突，且没有已知硬失败 |

Docker 镜像 index、manifest 与 image config ID 分型处理。无法证明旧 digest 属于同一种类型时，显示证据不足，不猜测“发布了旧版本”。当前 SSH 连接的主机密钥信任限制会持续展示，报告不能证明物理主机身份。

护航只读取冻结的连接和完整容器 ID。正常替换、回滚、连接或项目配置变化会终止旧对象的窗口，不自动跟随同名新容器，已发现的失败仍保留。关闭页面不停止后台任务；主动停止先显示“停止中”，在途观察退出后才确认停止。平台重启将旧任务标为中断，不重放采集或部署。

采样覆盖需要至少 90% 的预期点、首尾点及不超过 60 秒的间隔。SSH 排队或失败会消耗原窗口；不会通过延长窗口掩盖缺口。全局最多两个护航任务、两个并发 SSH 读取，每次状态读取总预算五秒。

## 本地变更调查

点击“调查”仅查询本机保留的证据、部署回执和仓库缓存，不访问模型或远端仓库。只有可信的即时发布前基线能关联到上一代实际容器，且两次部署都保有同仓库配置下的完整实际检出 SHA 时，才比较两个源代码树。比较仅包含最多 40 个文件路径和状态，不包含补丁正文。

历史部署候选会标明时间与缺失信息，不替代即时基线。异常在发布前已经存在时，会作为相应条件的反证；时间上的关联不会被当成因果关系。缓存缺失、忙碌或版本不可比时会明确说明。新增证据会使旧调查过期，需重新调查。

复验创建新报告并保留原报告；缩短窗口、减少目标等变化会明确列出，不能据此宣称原问题已修复。

## 可选 AI 解释

AI 默认关闭。即使实例已配置模型，护航也不会自动分享数据。需逐次选择结构化状态或已采集的脱敏日志，预览确切快照及接收方，再单独确认发送。此解释接口没有工具、部署或配置权限，也不能修改规则结论。

日志采集与模型分享是两次独立选择。日志只读取绑定容器最近至多 60 秒的窗口，每分钟最多一次，每次至多 32 KiB、每目标累计 256 KiB；报告证据总预算 2 MiB。截断、容量停止和时间缺口会明确记录。

模型目的地或证据变化后，旧确认不能发送。发送后的超时、中断或撤回可能仍产生费用，状态为“结果未知”，不会自动重发，也不能换另一份预览绕过限制。已发送的数据无法撤回。模型仅能给出有证据引用的候选解释；真实根因与修复仍需人工确认。

## 保留与清理

证据保留七天，报告摘要保留三十天。证据到期后无法读取旧快照或创建新解释；清理任务物理删除证据、日志、模型快照和调查明细。删除活跃报告前需先停止，项目删除会先取消并等待观察退出。运行历史清理不会让必要的部署身份快照丢失。

所有接口沿用登录认证、CSRF 与审计；跨项目 ID 被拒绝。此能力没有新增 MCP 运行工具、自动处置或遥测。
